## 3. How it was checked

- Inventory and scope: every claim, script, example and test in the skill was inventoried (3,323 items); risk-based scope put 317 in stage 1. 63 candidate lines were dismissed, each with a reason in the report.
- Verdicts: each in-scope item rests on commands that were run in a private copy of the skill (`workspace/` in the run folder, Python 3.13 venv; tool versions below) and recorded with their output. 6 searches were logged and 4 sources fetched raw (a flaky-test paper on arXiv twice, pytest's deprecations page and changelog); `validate_audit.py` string-matched every quote against the saved source text.
- Blind review: fresh reviewers, kept blind by a written brief, rechecked every checked item. Round 1: seven reviewers, 285 items, 46 problems left open. Round 2: two reviewers, 49 items, 14 open. Round 3: one reviewer, 19 items, 8 open. The cap is 3 rounds. At the cap, 2 items were disputed (I-W11-0026 and I-R3-0009; both are disagreements about the evidence, the two sides agree on the verdict) and 6 claims the reviewer found in the last round (R3-3318 to R3-3323, all about the Stop gate) were recorded as not checked. A reviewer on a different model from the auditors is stated in the run's brief; the files I read do not record the reviewers' model.
- "Wrong" counts only misses inside what a rule or docstring claimed to cover. Detector gaps beyond that went to the suggestions list, so the 172 suggestions held most of the missing detections; the fix pass therefore triaged every suggestion, not only the findings.
- Tool versions, from `uv pip list` on the audit venv on 2026-11-20: pytest 9.2.0, pytest-randomly 5.1.0, pytest-cov 7.1.0, pytest-timeout 2.4.0, pytest-asyncio 1.5.0, Hypothesis 6.170.17, crosshair-tool 0.0.114, mutmut 3.8.1, anyio 4.16.0, coverage 7.17.3, Python 3.13.2. The report also lists hypothesis-crosshair 0.0.32, syrupy 7.0.2 and pytest-xdist 3.8.0 from worker venvs.

Limitations of the method, as they happened:

- The scripts cannot prove that a reviewer stayed out of the auditor's files; the blindness rests on the brief.
- During the first fix round of the audit, four workers shared one workspace folder by mistake. It was caught mid-round; the affected results were rerun in separate copies and were reproduced in later blind rounds.
- The follow-up worker for log H wrote its three lock-in tests after the fixes, not test-first (the real check was shown failing by planting a `FLOAT_EQ` in a self-test).
- In the fix pass, five workers fixed their areas test first on disjoint files. One worker, adding new mutation kinds and killed-by reporting to `mutate_check.py` at the owner's request mid-pass, wrote code before tests for that round. Its evidence was recovered by running the new tests against the previous script: 60 failed, 114 passed.
- Workers ran mutation checks in place and at the same time under heavy machine load, so their mutation scores are provisional (section 7). The lead's sequential reruns on a private copy are the figures of record.
- A documentation worker then re-checked the docs against the code by running the tools. It found two more defects, fixed test first (log F): the Stop gate fingerprint missed four config file names (`.pytest.toml`, `.pytest.ini`, `pytest.toml`, `.coveragerc.toml`) and `audit_tests.py` with no path printed a message containing "None".
- The Claude Code hooks reference was fetched on 2026-11-20 by the hooks worker, for the code (what it relied on is in log D); `references/hooks.md` keeps its 2026-11-02 stamp for the doc text.
- The Atheris fuzz figures were not rerun: Atheris does not install on this machine.

## 4. Findings and what was done about each

57 findings: 48 wrong, 1 stale, 2 disputed, 6 not checked. By area: `scripts/audit_tests.py` 15, `scripts/diff_guard.py` 16, `scripts/mutate_check.py` 3, `scripts/flake_hunt.py` 2, the hooks 8, the self-tests 9, the wallet example 4. Status after the fix pass: 55 fixed, 2 already correct (R3-3322 and R3-3318, both Stop gate claims that were right and, in the second case, untested).

The most important ones, in plain words:

- A Stop gate that could pass without checking. With tests outside `tests/`, an unknown diff base, a missing or crashing audit or guard script, a timeout, or pytest exiting 5 (nothing collected), the gate let Claude stop as if everything were green. `PYTEST_EXPERT_MAX_BLOCKS=0` printed "gave up ... still red" before running anything. Now each case blocks or warns with a message that says what could not run (I-W12-0005, I-R3-0009, R3-3319 to R3-3323).
- The diff guard missed the edits it exists to catch. Git quoted non-ASCII paths and the guard dropped them, so a deleted `tests/test_ä.py` or a source file that gained `__eq__` returning `True` went unreported. Skips written as `np = pytest.importorskip(...)`, as `pytestmark` variants, as unittest skips or as the attached `-k'not bad'` in `addopts` were not seen. Deleting the config file that held `fail_under` reported clean. It also raised false alarms: rewriting `parametrize` rows as `argvalues=` looked like 3 rows lost, and adding `reason=` to a skip counted as a new skip (I-W11-0068, I-W11-0070, I-W11-0077, I-W11-0081, I-W11-0093, I-W11-0094, I-R3-0002, I-R3-0003 and others).
- Detectors that fired on the wrong thing or stayed silent on the right thing. `NETWORK` flagged `urllib.parse` and `http.HTTPStatus`; `UNSEEDED_RANDOM` flagged `default_rng(seed=42)`; `ALWAYS_TRUE` flagged `assert [*r]`, which can fail; `XFAIL_NOT_STRICT` misread pytest 9.2's `strict` fallback; a file with a byte-order mark was reported as a syntax error; a project under a directory named `build` was audited as nothing; the script was read as claiming 26 codes where it defines 25 and its docstring stated no count (I-W11-0001, I-W11-0024, I-W11-0027, I-W11-0013, I-W11-0038, I-W11-0047, I-W11-0048, and others).
- `mutate_check.py` counted any non-zero exit as a kill, so a mutant that broke the import looked killed (a suggestion, not a finding; the worker's probe killed 2 of 7 with mutant 1 a false kill), and it died with a traceback and exit 1, the "survivors" status, when the test command could not start. `flake_hunt.py` called a test driven by `random` "order-dependent" even with `--repeat-seed`, and exited 0 on `--runs 0`, on a path that selects no test, and on collection errors.
- Self-tests that could not fail. The Stop gate's "ignores non-test files" and "skips an unchanged tree" tests stayed green with their feature removed; the `flake_hunt.py` tests stayed green with outcomes inverted; the diff guard tests left non-equivalent mutants alive; the `mutate_check.py` tests killed 41 of 120 mutants of the script (I-W11-0242, I-W11-0243, I-W11-0236, I-W11-0203, I-W11-0251). The structure test never checked backticked paths with an anchor, or `.md` names that start with a digit.
- The wallet example. Its network guard did not block `socket.connect_ex` or UDP `sendto` (I-R2D-0001). `test_fee_is_never_negative` never reached the fee code: random ten-digit accounts all fail the mod-97 check, so every mutant in the fee body survived (I-W12-0290). The fuzz corpus replay passed values that were wrong (I-W12-0292). `transfer` left the source debited when the target's deposit failed (I-W12-0296).
